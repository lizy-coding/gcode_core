# 位图与混合预览 GPU 验证 · 2026-11-19

单张位图和三工序混合预览通过本轮 macOS 小样本像素验证。两轮 64 工序播放均出现持续的进程常驻内存增长，当前版本的多工序压力验收应暂停。冒烟时出现过一次混合画面首行异常，本轮未复现，仍需保留观察项。

## 环境和方法

- MacBook Air、Apple M5、24 GB 内存、macOS 27.0.1（26A434）、arm64。Flutter 3.47.2（`d3b14c876900e553bc736ca19295fc09e3853e8e`），引擎 `a804b261645ef8c13eb3d5c44a5c2fb0340c5539`，日志确认 Impeller MetalSDF。
- 基线为 `b4e7fb5` 加工作区位图与混合改动，文件散列见 [source-sha256.txt](source-sha256.txt)。两轮使用同一 Profile 产物，App.framework 中 App 的 SHA-256 为 `6dffb5219a67e179587f25712bc988db546764bb05b4a755530e20fbe7e7d86e`。
- 通过公开 `GcodeCanvas.bitmap` 和 `GcodeCanvas.mixed` 接口采集真实 GPU 画面。画布为 640 × 480 逻辑像素，设备像素比 2，PNG 以逻辑尺寸读回。每轮先做截图和大图检查，再各采样约 15 秒三工序与 64 工序。两组复用同一个 13 × 8 曝光图，矢量段数量相同，在 98% 与 100% 之间逐帧切换。64 工序包含 62 道复用同一纹理的位图工序。
- 两次进程主测试均退出成功。进程 RSS 包含 CPU 与 GPU 相关的驻留分配等开销，GPU 专用内存未直接测量。Flutter raster P95 是框架报告的帧时间，独立 GPU 命令耗时未测量。

## 渲染与资源结果

| 问题 | 观测 | 判断 |
|---|---|---|
| 混合预览偶发的首行空白变黑 | 两轮共 60 次跨工序跳至终点，每轮末帧的整图像素散列只有一个。单图首尾、末行折返、混合中间状态和终点共 7,280 个像素中心比对全部匹配。回退前后同进度画面逐像素相同。 | 本轮未复现。读回发生在帧结束后，未逐帧覆盖原生窗口合成过程，原异常仍未关闭。 |
| `onReady` 与纹理上传先后 | 小图、大图和混合场景在 0% 首帧均触发就绪，上传数均为 0。混合首次跳进位图工序后上传数为 1，反复回退及重播后仍为 1。 | 首帧就绪与首次纹理提交是两件事。第一次进入位图工序会承担上传成本。 |
| 大图上传与缩放 | 4096 × 4096 R8 两轮均只提交一次 16 MiB 纹理上传，矢量顶点上传为 0。缩窄画布后发生一次 surface 调整，上传次数仍为 1。首次从 0% 跳到 100% 的框架帧等待分别约 18.66 和 18.47 ms。 | 本机这张合成大图可显示并复用纹理。该时间包含帧调度，GPU 上传耗时和设备纹理上限仍待测。 |

## 工序规模对开销的影响

| 工序数 | 两轮有效计时样本 | UI P95 | Raster P95 | 两轮 RSS 增量 |
|---:|---:|---:|---:|---:|
| 3 | 906 / 905 | 1.00 / 1.00 ms | 0.60 / 0.59 ms | +2.50 / +3.02 MiB |
| 64 | 904 / 903 | 2.14 / 2.18 ms | 0.55 / 0.55 ms | +35.55 / +37.23 MiB |

RSS 增量取各阶段首末样本，间隔约 14 秒。两组纹理提交均为 104 字节，矢量顶点提交均为 1,176 字节。64 工序组从采样开始就持续增长，三工序组主要在开始时增长后趋稳。

当前渲染器为每道可见工序写入两份 uniform，并使用固定的 16 KiB `HostBuffer`。macOS Metal uniform 对齐为 256 字节。按两次辅助绘制和矢量底图占六份 uniform 估算，第 30 道可见工序附近开始跨块。Flutter 3.47.2 在跨块时追加分配，而帧间 `reset()` 只复位游标。该分配行为与实测趋势吻合，尚缺逐次分配追踪或修复前后对照来量化归因。

## 修复后验收

1. 优先让每帧的 uniform 写入落在可复用空间，按实际对齐和提交上限计算容量。复跑同一三工序与 64 工序样本，再做长时测量，确认缓冲分配数和稳态 RSS 趋势。
2. 明确 `onReady` 的首帧语义，单独观察素材首次上传与失败。用目标设备复测大图从首帧到素材可见的延迟和纹理超限反馈。
3. 对原偶发黑块，用实际预览控件采集更长的播放与跳转序列，补连续窗口画面与像素读回的交叉证据。ADB 中无可用 Android 设备，本轮 Android GPU 与 GLES 错误传播没有运行证据。

## 复现与原始数据

从 `example` 构建 `python3 tool/macos_run.py --mode profile --target lib/mixed_gpu_validation.dart --build-only`，再执行 Profile 应用的 `Contents/MacOS/example`。使用 `GCODE_GPU_OUTPUT` 指定应用可写的独立目录，例如 macOS 应用容器的 `Data/tmp` 下的本轮子目录。退出后使用 `python3 tool/check_mixed_gpu_pixels.py RUN_DIR [RUN_DIR ...]` 复核 PNG，检查脚本依赖 Pillow。
