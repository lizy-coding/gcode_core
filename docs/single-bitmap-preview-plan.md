# 第一阶段 · 单张位图扫描预览

目标是在示例中加载一张加工后位图，按假定的蛇形顺序展示曝光图案，支持播放、暂停和任意定位。实际打印指令、设备运动和加工时间仍取自原加工流程。本阶段交付包能力和示例验证，混合项目编排留给下一阶段。

## 1. 确定输入与坐标

- 调用方提供最终曝光栅格、宽高、像素间距以及从栅格到加工平面的变换。先用一张可人工对照的样图在 example 打通。接入生产项目时，再确认半色调、裁剪及旋转由哪个上游步骤完成，避免重复处理。
- 约定首行、首列和首行扫描方向，明确像素中心与加工边界的半像素偏移。栅格按固定行序存储，折返只影响显现顺序。校验尺寸、字节长度、有限且有效的间距和变换。
- 时间估算沿用原始指令。进度参数表示扫描覆盖比例，每行分配等量进度，空白行照常经过。

## 2. 实现一张纹理的播放

- 为单张位图增加明确的预览入口，接入现有 Flutter GPU surface、视口和合成流程。第一版使用固定四边形，把曝光值上传为设备支持的采样纹理。shader 源文件与编译产物一起维护。
- 将进度映射到已完成行数和当前行内位置。偶、奇行交替从两侧显现，空白像素保持空白。初始帧无已曝光像素，结束帧完整显示加工图案。拖动回退直接按目标进度绘制。
- 同一图片的播放只更新每帧参数。换图更新纹理，窗口缩放只更新映射与 surface。加载失败、替换图片及销毁画布时清理对应资源，避免旧图的就绪回调覆盖新图。超过当前设备纹理限制时给出明确错误。

## 3. 示例与验收

| 验证项 | 样本与通过条件 |
|---|---|
| 扫描规则 | 用非对称小图覆盖奇偶行、空白行、单行、单列及首尾像素。逐点核对 0%、行中、换行边界、100% 和回退后的曝光结果。 |
| 坐标与显示 | 用非正方形、带原点偏移的样图，在两种视口尺寸下对照四角像素和加工边界。全图完成时与输入曝光栅格一致。 |
| 播放开销 | 记录纹理上传次数和字节数、几何构建次数。一次成功加载只上传一次曝光纹理，连续播放、暂停、拖动和缩放的纹理上传增量为零。路径段数量与曝光点数量脱钩。 |
| 运行验收 | 运行包及示例测试。在受支持的 macOS、Android ARM64 上用同一张代表性大图记录首帧耗时、帧耗时分布、可获取的内存指标，以及反复换图后的表现。保留设备、系统、Flutter 和代码版本、图片尺寸及截图。 |

先完成小图的像素和坐标验收，再测大图。以实测纹理上限和内存数据决定是否另开分块纹理工作。仅持有 G-code 文本时从 G25 推断图像布局，需要单独设计输入识别与校验。
